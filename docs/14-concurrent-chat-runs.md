# Параллельные запуски

SubmitChatMessageRequest передаёт OperationId, MessageId, Content и режим Send, Queue, Fork или Replace. BranchId определяет ветку, ParentMessageId — точку ответвления, ReplaceSourceId — корень замены. ExpectedRevision защищает замену, HoldInQueue откладывает выполнение.

Повторный OperationId не добавляет команду второй раз. Очередь сохраняется до фиксации ответа. Генерации веток параллельны, изменения чата проходят через ChatSynchronization. HTTP-запрос не удерживает блокировку.

SSE передаёт последние снимки и может объединять промежуточные события. Клиент сравнивает Revision и ChatRevision, хранит выбранный ID ветки и берёт голову из актуального чата.

Stop отменяет генерацию. Resume возобновляет очередь, включая немедленное возобновление после Stop. При остановке Host workers отменяются и ожидаются. После перезапуска незавершённая работа получает Interrupted. Удаление сначала завершает workers.
