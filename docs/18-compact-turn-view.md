# Компактное представление хода в чате

Статус: Accepted (реализовано)

Набросок UI: [sketches/compact-turn-view.html](sketches/compact-turn-view.html) — открывается в браузере, содержит все состояния строки в цветах приложения.

## Задача

Один ход модели (от сообщения пользователя до финального ответа) сейчас разворачивается в ленте в несколько статей: каждая пара «промежуточное рассуждение + вызовы инструментов» — отдельный блок. Ход из пяти циклов занимает экран целиком, и финальный ответ уезжает вниз.

Требование: по умолчанию показывать только диалог — сообщение пользователя, финальный ответ, статистику изменений файлов. Промежуточные сообщения сворачиваются в **одну строку**, по клику разворачиваются в сегодняшний вид без изменений.

## Что уже есть

- [`ChatFeed.BuildFeedItems`](../src/AI.Client.Web/Components/ChatFeed.cs) проецирует плоскую цепочку сообщений ветки на элементы ленты: либо одиночное сообщение, либо группа «преамбула + вызовы инструментов».
- [`MessageFeed.razor`](../src/AI.Client.Web/Components/MessageFeed.razor) рендерит эти элементы; `GetRenderedFeedItems()` берёт хвост списка по `_renderedItemLimit`.
- [`ToolActivityGroup`](../src/AI.Client.Web/Components/ToolActivityGroup.razor) уже сворачивает батч вызовов в одну строку-сводку и раскрывает строки по клику. **Этот компонент не меняется.**
- [`WorkspaceChanges`](../src/AI.Client.Web/Components/WorkspaceChanges.razor) — карточка «N files changed». **Не меняется.**
- `composer-status` в [`Home.razor`](../src/AI.Client.Web/Pages/Home.razor) показывает `Generating… 12s` и подсказки про Enter. **Не меняется, ничего нового над областью ввода не добавляется.**

## Решения

### Граница хода

Ход — отрезок ленты от сообщения пользователя (не включая его) до следующего сообщения пользователя или конца ветки.

Внутри хода **финальный ответ** — последний элемент отрезка, если это одиночное сообщение ассистента без вызовов инструментов. Всё остальное внутри отрезка — **промежуточные сообщения**: и группы инструментов, и текстовые сообщения ассистента без инструментов.

Ход может закончиться без финального ответа (остановлен, упал) — тогда промежуточными являются все элементы отрезка.

### Свёрнутая строка

Одна строка на ход, на месте всех промежуточных сообщений — то есть между сообщением пользователя и финальным ответом.

| Состояние хода | Текст строки |
| --- | --- |
| Идёт | текущее действие модели + время: `Соберу данные по использованию классов… · 12s` |
| Завершён | `Worked for 1m 13s` |
| Остановлен пользователем | `Stopped after 22s` |
| Упал | `Failed after 22s` |
| Промежуточных сообщений не было | строки нет вообще |

Только время — ни числа шагов, ни числа вызовов, ни бейджа ошибок. Про ошибки видно после раскрытия: там сегодняшний `ToolActivityGroup` со своим `N failed`.

«Текущее действие» — содержимое последнего промежуточного сообщения ассистента (преамбулы), обрезанное до одной строки. Если модель ещё ничего не написала в этом ходе — `Working for 12s`.

### Раскрытие

- Клик по строке раскрывает ход: строка остаётся на месте как заголовок (шеврон поворачивается вниз), под ней рендерится **сегодняшняя разметка без изменений** — статьи `workspace-message tool-group` с преамбулами и `ToolActivityGroup`, статьи промежуточных текстовых сообщений.
- Раскрытие накопительное: несколько ходов могут быть раскрыты одновременно, каждый сворачивается отдельно.
- Состояние раскрытия **не сохраняется**: при открытии чата все ходы свёрнуты. Ни `localStorage`, ни настройки.
- Отдельного переключателя «компактно / подробно» нет. Строка — единственный орган управления, и он работает по одному ходу.
- Активные вызовы инструментов рендерятся в конце раскрытого текущего хода. Потоковый ответ показывается обычным сообщением вне строки, пока неизвестно, станет ли он финальным. Если провайдер возвращает вызовы инструментов, последняя потоковая версия за `240ms` затухает, сдвигается вверх и схлопывается в закрытую строку хода; сама строка коротко подсвечивает приём. В раскрытом ходе внешний поток просто заменяется сохранённым промежуточным блоком. Если вызовов нет, сообщение остаётся снаружи и без перехода становится финальным ответом.

### Что остаётся видимым при свёрнутом ходе

- Сообщения пользователя и финальный ответ.
- Карточка `WorkspaceChanges` — **всегда**, даже если она принадлежит скрытому промежуточному сообщению. Сейчас она рендерится рядом с `item.Message`; при скрытии сообщения сама карточка должна остаться.
- Карточка `turn-status` (Retry / Continue / Discard) — как сейчас.
- Отдельного `tool-activity-live` вне хода нет. Потоковый текст остаётся снаружи до момента, когда становится известно, что это промежуточная преамбула, чтобы пользователь всегда видел живую генерацию возможного финального ответа.

## Набросок

Свёрнуто:

```
                         Посмотри где классы используются без DI   ← сообщение пользователя

Worked for 1m 13s  ›                                               ← строка хода

Без интерфейсов и вне DI создаются 7 классов…                      ← финальный ответ

┌──────────────────────────────────────────────────┐
│ ⎌  3 files changed                 +128  −14   ⌄ │              ← WorkspaceChanges, как сейчас
└──────────────────────────────────────────────────┘
```

Идёт ход:

```
                         Посмотри где классы используются без DI

◌ Соберу данные по использованию классов… · 12s  ›                 ← текст меняется с каждым шагом
```

Раскрыто:

```
Worked for 1m 13s  ⌄

  Изучу структуру и точки регистрации DI.                          ← сегодняшняя разметка,
  ✓ Tools finished        1 tool call            164 ms               ничего не изменено

  Соберу данные по использованию классов в Web/Cli/Host.
  ✓ Tools finished        8 tool calls · 1 failed  2.2 s

Без интерфейсов и вне DI создаются 7 классов…
```

## Оформление

Строка тихая: без рамки, без фона, выровнена по левому краю колонки сообщений.

- Размер и цвет — как у `.tool-row`: `font-size: 0.76rem`, `color: #8a8a8a`, `:hover` → `#b4b4b4`.
- Шеврон — `AppIcon Name="chevron-right"`, `0.85rem`, `#6f6f6f`; в раскрытом состоянии `chevron-down` через `transform: rotate(90deg)` с переходом `200ms cubic-bezier(0.2, 0.8, 0.2, 1)` — та же кривая, что у `.workspace-changes-chevron`.
- Во время хода слева спиннер `AppIcon Name="spinner" Class="tool-row-spinner"`.
- Время — `font-variant-numeric: tabular-nums`, чтобы строка не дёргалась посекундно.
- Текст текущего действия — одна строка, `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`. Высота строки фиксирована независимо от длины текста.
- Формат длительности — существующий `FormatDuration` из `ToolActivityGroup` (`164 ms` / `2.2 s` / `1m 13s`).
- Формулировки английские (см. language convention в [README](README.md)): `Working for …`, `Worked for …`, `Stopped after …`, `Failed after …`.

## Реализация

### Состав изменений

1. **`ChatFeed`** — научить строить границы хода. Нужен признак принадлежности элемента ходу и признак «это финальный ответ». Варианты: добавить в `FeedItem` поле `TurnId` (id сообщения пользователя, открывшего ход) и флаг `IsFinalAnswer`, либо отдельный метод `BuildTurns(...)`, возвращающий элементы, сгруппированные по ходам. Второе предпочтительнее: правила упорядочивания в `ChatFeed` покрыты тестами, и новая проекция тестируется так же.
2. **`MessageFeed.razor`** — в `GetRenderedFeedItems()` промежуточные элементы нераскрытого хода заменяются одним элементом-строкой. Раскрытые ходы отдают сегодняшний набор элементов без изменений.
3. **Состояние** — `HashSet<Guid> _expandedTurns` по id сообщения пользователя, открывшего ход. Не персистится.
4. **`TranscriptRenderBoundary`** — добавить параметр, отражающий набор раскрытых ходов (например, их количество и хеш), иначе `ShouldRender` не заметит клик и лента не перерисуется.
5. **CSS** — новые правила `.turn-summary` рядом с блоком `.tool-row` в `app.css`.

### Длительность хода

- Завершённый ход: `CreatedAt` последнего сообщения хода минус `CreatedAt` сообщения пользователя.
- Идущий ход: уже существующий счётчик из `Home.razor` (`GetGeneratingElapsed`), передать его в `MessageFeed` параметром, а не заводить второй таймер — иначе два тикающих таймера разойдутся.

### Скролл

Раскрытие и сворачивание меняют высоту ленты сильно. В проекте уже есть якорение скролла (см. историю коммитов про scroll anchoring). Требование: после клика сама строка остаётся на том же экранном месте — якорем служит она, а не низ ленты. Автоскролл к низу при этом не должен срабатывать: клик по строке — не приход нового контента.

### Форк и ветки

Кнопки «Fork from here» и индикатор веток сейчас висят на статьях промежуточных сообщений. При свёрнутом ходе они недоступны — это принято сознательно: чтобы форкнуть с промежуточного шага, ход нужно раскрыть. Классы `branch-leaf`, `branch-leaf-arrived`, `fork-source` не должны потеряться: если якорь скрытого хода несёт один из них, строка обязана отобразить соответствующее состояние либо ход должен раскрываться принудительно (например, когда `ForkSourceId` указывает внутрь него).

### Производительность

`_renderedItemLimit` считает элементы ленты. После свёртки ход даёт один элемент вместо многих, поэтому начальный хвост охватит больше диалога — это желаемый эффект, но константу `InitialRenderedItemCount` стоит перепроверить. Разметку раскрытого хода строить только когда он раскрыт (как это сделано с диффами в `WorkspaceChanges`, где `<details>` сознательно не используется).

## Критерии приёмки

1. Ход с инструментами свёрнут в одну строку; лента содержит сообщение пользователя, строку, финальный ответ и карточку изменений.
2. Клик по строке раскрывает ход в точности в сегодняшнем виде; повторный клик сворачивает.
3. Два раскрытых хода остаются раскрытыми одновременно.
4. Переоткрытие чата возвращает все ходы в свёрнутое состояние.
5. Во время генерации строка показывает текущее действие модели и растущее время; лента при этом не растёт по числу элементов.
6. Ход без промежуточных сообщений не добавляет строку.
7. Остановленный и упавший ходы показывают `Stopped after …` / `Failed after …`.
8. Карточка изменений файлов видна при свёрнутом ходе.
9. Над областью ввода ничего не изменилось.

## Как это устроено у других

Для контекста при возможном пересмотре решения:

- ChatGPT, Claude.ai, Cursor, Copilot agent, Windsurf — промежуточные шаги остаются в ленте свёрнутыми; после хода — строка вида «Thought for 23s», раскрывающая сводку.
- Devin выносит прогресс из чата в отдельную панель-таймлайн.
- Claude Code (CLI) показывает текущее действие в строке над промптом, лента при этом не растёт.

Выбранный здесь вариант ближе всего к ChatGPT: одна строка-остаток на ход, раскрывающаяся по клику.
